# Choose the deploy target when creating a project

## Intent

The maintainer wants every starter to ask, at `npm create` time, where the app will be deployed, and to support all
the serverless platforms mion has adapters for (Vercel, Cloudflare, AWS, plus a plain Node or Bun server). Today each
starter hard-codes its own set of targets, and some of them never worked (the old Vercel layouts).

Blocked until the React, Vue and Nuxt starters are on mion 0.13: they set the shape this builds on.

## Direction

The implementer plans the details. Known context:

- mion adapters: `@mionjs/platform-node`, `-bun`, `-vercel`, `-cloudflare`, `-aws`, `-gcloud`, `-uws`. Edge
  runtimes need `runTypes.emitMode: 'both'`.
- One target per project: a real app deploys to one place, so `create.mjs` would add only the chosen target's entry
  file, build script, config (`wrangler.toml`, Vercel output, AWS template) and dependency.
- Vercel without Next: Vercel treats every file in a root `api/` folder as a function, which clashes with the
  starters' `api/src/` source folder. The idea noted during the investigation: a post-build step that writes the
  Build Output API layout (`.vercel/output/` with `static/`, a function for `/api/mion/*`, and `config.json`).
  Unverified.
- Each starter stays an independent package, so shared target recipes have to be copied into each starter or
  generated by `create.mjs`.
- Investigation background: `docs/investigations/mion-0.13-migration/` on the `claude/focused-feynman-3p5dap`
  branch (deploy findings per starter).

## Docs

Each starter's `README.md` deploy section and `CLAUDE.md` ("Creating a New Project").

Before opening the PR, run the simplify-docs pass (the `docs-simplifier` subagent) over every page and example
this change touched, review its report against the code, and commit it as its own commit.

## Done when

- `npm create` for each starter asks for the target and the created project deploys to it, each target verified
  as far as possible without accounts (local runtimes such as workerd, handler calls with real requests).
- The simplify-docs pass ran on every touched page and the simplify-comments pass on every touched source file,
  each committed on its own.
